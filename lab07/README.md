This lab focuses on **string algorithms and text-related data structures**. It moves from simple pattern searching to faster searching, then to tries, compression, and dynamic programming.

| Step | Concept                               | Simple description                                                                                                | Example                                                                                         |
| ---- | ------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| 1    | **Brute-force string search**         | Check every possible position in the text to see if the pattern starts there.                                     | Text: `"banana"`, pattern: `"ana"` → first match starts at index `1`.                           |
| 2    | **All pattern matches**               | Find every place where the pattern appears, including overlapping matches.                                        | Text: `"aaaaa"`, pattern: `"aa"` → matches at `[0, 1, 2, 3]`.                                   |
| 3    | **Boyer-Moore last-occurrence table** | Store the last position of each character in the pattern. This helps skip ahead after a mismatch.                 | Pattern: `"abacab"` → `a = 4`, `b = 5`, `c = 3`, missing character = `-1`.                      |
| 4    | **Boyer-Moore search**                | Compare from right to left and use the last-occurrence table to jump forward when characters do not match.        | Text: `"the quick brown fox"`, pattern: `"brown"` → match starts at index `10`.                 |
| 5    | **KMP failure function**              | Build an array that tells how much of the pattern can be reused after a mismatch.                                 | Pattern: `"abacab"` → failure array `[0, 0, 1, 0, 1, 2]`.                                       |
| 6    | **KMP search**                        | Use the failure function to avoid restarting the search from scratch after a mismatch.                            | Text: `"aaaaab"`, pattern: `"aaab"` → match starts at index `2`.                                |
| 7    | **Standard trie**                     | Store words in a tree where each edge is a character. Useful for fast word and prefix lookup.                     | Insert `"bear"` and `"bell"`. Prefix `"be"` exists, word `"bear"` exists, word `"be"` does not. |
| 8    | **Trie autocomplete**                 | Find the node for a prefix, then collect all words below that node.                                               | Words: `"stock"`, `"stop"`, `"sell"`. Prefix `"sto"` → `"stock"`, `"stop"`.                     |
| 9    | **Huffman coding**                    | Compress text by giving shorter binary codes to frequent characters and longer codes to rare characters.          | Text: `"AAAAABBC"` → `A` should get a short code because it appears most often.                 |
| 10   | **Longest Common Subsequence, LCS**   | Find the longest sequence that appears in both strings in the same order, but not necessarily next to each other. | `"ABCBDAB"` and `"BDCABA"` → LCS length is `4`, such as `"BCBA"`.                               |
